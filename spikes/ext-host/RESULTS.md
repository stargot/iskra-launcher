# Спайк: ext-host — out-of-process плагины, JSON-RPC 2.0 over stdio (NDJSON)

Снятие риска фазы 0 по `docs/specs/2026-09-17-windows-raycast-clone-spec.md`, §4.2 решение 3.
Окружение: Windows 11, Node v24.15.0. Дата: 2026-09-17.

## Методика

- `plugin.mjs` — референс-плагин: читает NDJSON из stdin, отвечает на `initialize` →
  `{ok:true, commands:["demo"]}` и `onQuery` → `{items:[3 элемента]}`; конверт JSON-RPC 2.0,
  одно сообщение на строку stdout.
- `host.mjs` — хост: спавнит `node plugin.mjs` как child process, RPC-клиент с per-call
  таймаутами; неожиданный выход плагина → in-flight вызовы реджектятся, эмитится событие-«тост».
- Замеры: `performance.now()`, p95 — nearest-rank. Холодный старт — 10 циклов spawn→ответ
  `initialize`; тёплый onQuery — 100 последовательных запросов в один живой процесс.
- Запуск: `node host.mjs` — все 4 теста автоматом, код возврата 0, в конце сводка.

## Вердикт: бандлить Node или требовать установленный

Для MVP рекомендую **не бандлить Node через SEA, а требовать установленный Node** (с понятной
проверкой при старте и инструкцией/ссылкой), потому что SEA-бинарник весит ~88 MB — это
перечёркивает главное преимущество Tauri-лончера (дистрибутив 5–10 MB), при том что добавленная
ценность бандла — только гарантированный рантайм для хоста плагинов. Целевая аудитория MVP
(power users, разработчики плагинов) почти поголовно имеет Node, а хост — единственный
Node-процесс, который в перспективе можно переписать на Rust, убрав зависимость целиком.
SEA оставить как запасной путь для «корпоративных» сборок/пользователей без Node: механика
рабочая (собирается за минуты, запускается), просто размер в дистрибутив MVP не влезает.
Бонус: изоляция и латентность протокола подтверждены — холодный старт 46 мс (против ожидаемых
100–300 мс), тёплый запрос 0.11 мс, kill упавшего/зависшего плагина ~5 мс без вреда хосту.
