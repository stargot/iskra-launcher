# Iskra — План реализации MVP

> **На основе:** [docs/specs/2026-09-17-windows-raycast-clone-spec.md](2026-09-17-windows-raycast-clone-spec.md)
> **Дата:** 2026-09-17
> **Допущение:** 1 разработчик, ~6 ч фокусного времени в день; оценки — рабочие дни.

---

## 1. Обзор

Доводим Iskra от пустой директории до закрытой беты за **7 фаз, ~31–41 рабочий день
чистой разработки (+30% буфера ≈ 42–54 дня ≈ 8–11 недель)**. Порядок фаз — по
снижению технического риска и по принципу «каждая фаза даёт продукт, которым
можно пользоваться». Фаза 0 (spike) сознательно идёт первой: гасит главные
неизвестные — квирки Windows API, память WebView2 и вес Node-рантайма — до того,
как заложена архитектура.

## 2. Фазы реализации

### Фаза 0: Spike — снятие технических рисков (оценка: 3–4 дня)

**Цель фазы:** доказать на прототипах, что ключевые допущения спеки достижимы,
и закрыть решения по открытым вопросам фазы 0.

**Задачи:**
- [ ] Spike «окно»: Tauri 2 frameless + acrylic/mica, позиционирование, per-monitor DPI
- [ ] Spike «хоткей»: `RegisterHotKey` → показ окна, скрытие при потере фокуса; замер p95
- [ ] Spike «клипборд»: `AddClipboardFormatListener`, приём текста и изображений
- [ ] Spike «плагин»: Node-процесс, JSON-RPC over stdio, эхо-запросы, таймаут + kill
- [ ] Замеры: RAM idle WebView2, размер инсталлятора, размер Node 22 SEA
- [ ] Решение: бандлить Node-рантайм или требовать установленный (пункт из §7 спеки)

**Зависимости:** нет.
**Критерий завершения:** хоткей→окно p95 < 150 мс на прототипе; клипборд ловит
копирования; плагин-эхо отвечает и убивается по таймауту; решения по Node и
замерам зафиксированы письменно.

### Фаза 1: Скелет лончера — shell, окно, хоткей (оценка: 4–5 дней)

**Цель фазы:** резидентное приложение, которое живёт в трее и мгновенно
показывает пустой список по `Alt+Space`.

**Задачи:**
- [ ] Структура репозитория: cargo workspace (`core`, `sys`, `tauri-app`) + UI-пакет
- [ ] Окно лончера: frameless, позиция «центр-верх активного монитора», DPI
- [ ] Hotkey service: регистрация, переназначение в настройках, конфликт-хендлинг
- [ ] Скрытие при потере фокуса; поведение поверх fullscreen
- [ ] Трей: иконка, меню (настройки/выход), автозапуск (реестр `Run`)
- [ ] Контракт IPC UI↔core (Tauri commands/events) — зафиксировать как модуль типов
- [ ] Настройки-заготовка: тема dark/light, хоткей, автозапуск

**Зависимости:** Фаза 0 (подтверждённые паттерны окна и хоткея).
**Критерий завершения:** `Alt+Space` → окно p95 < 100 мс; скрытие при blur;
RAM idle ≤ 80 МБ; автозапуск и трей работают.

### Фаза 2: Ядро поиска — движок + встроенные провайдеры (оценка: 6–8 дней)

**Цель фазы:** лончером уже можно пользоваться ежедневно, без плагинов.

**Задачи:**
- [ ] `SearchProvider` trait + агрегатор: параллельный опрос, склейка ранжирования
      (fuzzy-score + приоритет + частота использования)
- [ ] Fuzzy-ранжирование fzf-like; юнит-тесты на корпусов запросов
- [ ] Провайдер «приложения»: парсинг Start Menu, кэш иконок, запуск
- [ ] Провайдер «настройки Windows» (ms-settings:) — топ-50 URI
- [ ] Калькулятор/конвертер (выражения, единицы, валюты — без сети: курсы позже)
- [ ] Системные команды: lock/sleep/restart/выключение монитора/empty bin
- [ ] Fallback «искать в интернете» (браузер по умолчанию)
- [ ] Файловый индекс: инкрементальная индексация папок пользователя → SQLite FTS5,
      фоновый воркер с прогрессом
- [ ] Пустой запрос: недавние/частые (обучение на выборе пользователя)
- [ ] Агрегация результатов асинхронно: UI не ждёт медленных провайдеров

**Зависимости:** Фаза 1 (окно, IPC).
**Критерий завершения:** поиск < 20 мс на 10 000 записей; приложения запускаются;
скролл 60 FPS; файлы из папок пользователя находятся по обрывку имени.

### Фаза 3: Клипборд-история + сниппеты (оценка: 4–5 дней)

**Цель фазы:** киллер-фича №1 — история клипборда, переживающая перезагрузку.

**Задачи:**
- [ ] Clipboard manager: слушатель, текст/изображения/файлы, запись в SQLite,
      лимиты (1000 записей / 200 МБ) и политика вытеснения
- [ ] UI клипборда: вход из лончера, поиск, pin, превью изображений
- [ ] Вставка в активное окно: эмуляция `Ctrl+V` (`SendInput`) с возвратом фокуса
- [ ] Сниппеты: CRUD в настройках, вставка из лончера
- [ ] Настройки: вкл/выкл мониторинга, исключения приложений, лимиты

**Зависимости:** Фаза 2 (модель команд и навигация).
**Критерий завершения:** 1000 записей, переживает перезагрузку, вставка в
стороннее приложение работает (проверить: терминал, браузер, Office, UWP).

### Фаза 4: Window management (оценка: 2–3 дня)

**Цель фазы:** 6 команд управления окнами из спеки.

**Задачи:**
- [ ] Window manager: `SetWinEventHook` + DWM, определение активного окна, UWP-квирки
- [ ] Команды: left/right half, maximize, move to next monitor, center, restore
- [ ] Опциональные хоткеи на команды (в настройках, по умолчанию выключены)

**Зависимости:** Фаза 2 (модель команд).
**Критерий завершения:** 6 команд работают в сценариях из спеки, включая UWP-окна.

### Фаза 5: Плагинная система + SDK (оценка: 8–10 дней)

**Цель фазы:** работающая экосистема: установка из git-репо, изоляция,
разрешения, 5 first-party плагинов.

**Задачи:**
- [ ] Манифест (`iskra` в `package.json`) + валидация + установка из git-репо
- [ ] Extension host: жизненный цикл процессов, `initialize/onOpen/onQuery/onAction`
- [ ] Сериализация UI-дерева: `List/Item/Form/Detail/Action`, рендер в общем UI
- [ ] Модель разрешений: проксирование `fetch/storage/clipboard`, ошибки без permission
- [ ] Надёжность: таймауты `onQuery`, kill зависших, toast при падении, рестарт хоста
- [ ] SDK `@iskra-launcher/sdk`: MVP-эргономика (функция возвращает массив `Item`; JSX — позже)
- [ ] Storage API плагинов (изолированное namespace)
- [ ] First-party плагины: npm search, GitHub repos, emoji, перевод, kill-process
- [ ] Прогрев часто используемых плагинов (скрытие 100–300 мс старта)

**Зависимости:** Фазы 1–2 (shell, агрегатор поиска); частично параллелится с фазами 3–4.
**Критерий завершения:** бесконечный цикл в плагине не блокирует UI;
плагин без `clipboard.read` получает ошибку доступа; 5 плагинов работают.

### Фаза 6: Полировка + закрытая бета (оценка: 4–6 дней)

**Цель фазы:** релиз-кандидат, отданный первым 5–10 пользователям.

**Задачи:**
- [ ] First-run онбординг (хоткей, права, что умеет)
- [ ] Полировка UI: иконки, анимации, пустые состояния, акцентный ряд результатов
- [ ] Производительность: прогрев, профилирование памяти, повторные замеры §8
- [ ] Логи + краш-репорты (локальные, с понятным путём в issues)
- [ ] Инсталлятор (NSIS/MSI), решение по код-подписи (сертификат — внешняя зависимость)
- [ ] Документация: README, гайд разработчика плагинов
- [ ] Прогон всех чекбоксов §8 спеки; рассылка беты

**Зависимости:** Фазы 3–5.
**Критерий завершения:** все чекбоксы §8 спеки закрыты или осознанно
перенесены с записью причины; бета установлена у 5+ внешних пользователей.

## 3. График зависимостей

```
Фаза 0 ──→ Фаза 1 ──→ Фаза 2 ──→ Фаза 3 ──┐
                       │                   │
                       ├──→ Фаза 4 ────────┼──→ Фаза 6
                       │                   │
                       └──→ Фаза 5 ────────┘
```

- Последовательно обязательно: 0 → 1 → 2.
- Фазы 3, 4, 5 зависят от фазы 2, но независимы друг от друга — при появлении
  второго разработчика идут параллельно (3 и 5 — самые ёмкие, их разводить
  в первую очередь).
- Фаза 6 — всегда последняя.

## 4. Оценки (сводка)

| Фаза | Оценка | Буфер (+30%) |
|------|--------|--------------|
| Фаза 0: Spike | 3–4 д | ~1 д |
| Фаза 1: Скелет лончера | 4–5 д | ~1,5 д |
| Фаза 2: Ядро поиска | 6–8 д | ~2–2,5 д |
| Фаза 3: Клипборд + сниппеты | 4–5 д | ~1,5 д |
| Фаза 4: Window management | 2–3 д | ~1 д |
| Фаза 5: Плагины + SDK | 8–10 д | ~2,5–3 д |
| Фаза 6: Полировка + бета | 4–6 д | ~1,5–2 д |
| **Итого** | **31–41 д** | **~11–12,5 д** |

**Итого с буфером: ~42–54 рабочих дня ≈ 8–11 недель календарных** для одного
разработчика. Оценки предварительные: уточняются после фазы 0 и фазы 2.

## 5. Риски и зависимости

### Внутренние риски
- **Скоуп-крип в фазах 2 и 5** (самые «интересные» для полировки) — правило
  «новая идея → бэклог»; критерий завершения фазы не расширяется задним числом.
- **Файлы/клипборд: недооценка квирков** — митигировано фазой 0, при неприятных
  открытиях скоуп фаз 3–4 пересматривается до их старта.
- **Усталость одиночной разработки** — ежедневный dogfood с фазы 2 держит
  мотивацию; фаза 5 разбита на подсистемы, чтобы прогресс был видимым.

### Внешние зависимости
- **Код-подпись:** сертификат (для фазы 6; EV — после валидации продукта).
  Без подписи SmartScreen будет ругаться — предупредить бета-тестеров.
- **Everything SDK** (опциональный провайдер): внесён в бэклог post-MVP,
  чтобы не блокировать фазу 2.
- **Node 22 SEA:** если размер/стабильность не устроят — фолбэк «требовать
  установленный Node» (решение в фазе 0).

## 6. Что НЕ входит в план

Всё из анти-целей спеки (§3.2): macOS/Linux, облачная синхронизация, store
плагинов, AI/LLM, авто-подстановка сниппетов. Плюс осознанно за рамками MVP:

- Интеграция Everything SDK (бэклог post-MVP).
- JSX/React-эргономика SDK (MVP — массивы `Item`; JSX — после беты).
- Локализация UI (только английский в MVP; русский — post-MVP).
- Валютный конвертер с онлайн-курсами.
- Автообновления (бета обновляется переустановкой).

- [ ] **Checkpoint 2 (конец фазы 2):** внутренняя альфа — начал пользоваться

      канал обратной связи (issues/Discord) работает.
- [ ] **Checkpoint 4 (перед бетой, фаза 6):** прогон чек-листа §8 спеки,
      замеры производительности зафиксированы, инсталлятор проверен на чистой VM.
